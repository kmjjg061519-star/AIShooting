# 게임 기획서: 스카이 가디언즈

## 1. 게임 개요

- 장르: 2D 비행 슈팅
- 시점: 세로형 탑뷰
- 플랫폼: PC 프로토타입
- 플레이 방식: 플레이어가 비행체를 조작해 적의 공격을 피하고 적을 격추한다.
- 핵심 목표: 이동, 조준 및 발사, 적 생성과 전투, 피격 및 처치, 재시작으로 이어지는 핵심 플레이 루프를 검증한다.

## 2. 핵심 컨셉

### 2.1 한 줄 컨셉

- 세로로 전진하는 전장에서 적의 탄막을 피하고 빠르게 적을 격추하는 직관적인 비행 슈팅 게임

### 2.2 핵심 플레이 경험

- 간단한 이동과 발사만으로 즉시 전투에 참여한다.
- 좁은 공간에서 적과 탄환 사이를 피하는 긴장감을 제공한다.
- 연속 격추와 생존을 통해 짧고 반복 가능한 성취감을 제공한다.
- 사망 후 빠르게 재시작하여 플레이 숙련도를 높인다.

### 2.3 화면 및 공간 구성

- 기준 화면: 1024×2048 세로형 화면
- 카메라: 원근감이 없는 Orthographic 탑뷰
- 플레이 영역: 월드 YZ 평면
- 진행 방향: 화면 아래에서 위로 전진하는 흐름
- 플레이어 위치: 화면 하단을 중심으로 이동
- 적 등장 위치: 화면 상단 및 좌우 가장자리

### 2.4 전투 컨셉

- 플레이어는 이동과 조준 및 발사를 동시에 수행한다.
- 일반 적은 단순한 이동과 공격 패턴으로 역할을 구분한다.
- 플레이어와 적의 공격은 명확한 시각 효과로 판별할 수 있어야 한다.
- 피격, 적 처치, 플레이어 사망은 즉시 알아볼 수 있게 표현한다.

### 2.5 진행 컨셉

- 적이 순차적으로 등장하며 전투 밀도가 점차 증가한다.
- 플레이어는 가능한 오래 생존하며 적을 처치한다.
- 플레이 종료 조건은 플레이어 사망이다.
- 게임 오버 후 즉시 같은 전투를 다시 시작할 수 있다.

### 2.6 프로토타입 범위

- 포함: 이동, 조준 및 발사, 적 생성, 단순 AI, 피격, 처치, 게임 오버, 재시작
- 제외: 성장 시스템, 장비, 상점, 스토리, 네트워크 플레이, 영구 저장

## 3. 핵심 메커니즘

### 3.1 공통 규칙

- 플레이 평면: 월드 YZ 평면
- 화면 방향: 오른쪽 `+Y`, 왼쪽 `-Y`, 위쪽 `+Z`, 아래쪽 `-Z`
- 고정 축: 모든 게임플레이 액터는 이동 중 월드 X 좌표 유지
- 입력 분리: 플레이어 이동은 `WASD`, 총알 발사는 방향키 사용
- 충돌 방식: 충돌 컴포넌트의 Overlap 이벤트 사용
- 종료 조건: 플레이어 HP가 0이 되면 게임 오버

### 3.2 플레이어

#### 역할

- `WASD`로 이동하고, 방향키 입력으로 해당 방향의 플레이어 총알을 생성한다.
- 적과 충돌하면 HP가 감소하고, HP가 0이 되면 사망한다.

#### 기본 설정

| 항목 | 프로토타입 기본값 |
| --- | --- |
| 시작 HP | 3 |
| 이동 속도 | 800 uu/s |
| 발사 간격 | 0.2초 |
| 이동 키 | W, A, S, D |
| 발사 키 | 방향키 위, 아래, 왼쪽, 오른쪽 |

#### 이동

1. `MoveHorizontal` 축의 `A`, `D` 입력을 월드 Y축에 적용한다.
2. `MoveVertical` 축의 `W`, `S` 입력을 월드 Z축에 적용한다.
3. 입력 벡터의 크기를 1로 제한해 대각선 이동 속도를 보정한다.
4. 이동 속도와 `DeltaTime`을 적용한다.
5. 카메라 가시 영역 안으로 Y, Z 위치를 제한한다.
6. 이동 후 X 좌표를 시작 X 좌표로 고정한다.

#### 공격

1. 방향키 입력이 들어오면 발사 가능 여부를 확인한다.
2. 위, 아래, 왼쪽, 오른쪽 방향키의 입력 상태를 YZ 발사 벡터로 조합한다.
3. 서로 반대인 방향키를 동시에 누르면 해당 축 입력을 0으로 처리한다.
4. 두 축을 함께 누른 대각선 입력은 방향 벡터를 정규화한다.
5. 유효한 발사 벡터가 있을 때 플레이어 바깥의 해당 방향 발사 지점에서 총알을 생성한다.
6. 방향키를 누르고 있는 동안 0.2초 간격으로 반복 발사한다.
7. 모든 방향키를 놓으면 발사를 중지한다.
8. 사망 상태에서는 총알을 생성하지 않는다.

#### 피격 및 사망

1. 적과 Overlap되면 HP를 1 감소시킨다.
2. 충돌한 적 하나당 피해를 한 번만 적용한다.
3. HP가 0이면 이동, 발사, 추가 피격을 중지한다.
4. 게임 오버 상태로 전환하고 재시작 입력을 대기한다.

#### 구현 체크리스트

- [ ] A, D 입력이 월드 Y축 이동으로 적용된다.
- [ ] W, S 입력이 월드 Z축 이동으로 적용된다.
- [ ] 이동 중 월드 X 좌표가 변하지 않는다.
- [ ] 대각선 이동 속도가 단일 축 이동 속도를 초과하지 않는다.
- [ ] 방향키 입력이 플레이어 이동에 영향을 주지 않는다.
- [ ] WASD 입력이 총알 발사 방향에 영향을 주지 않는다.
- [ ] 누른 방향키의 방향이 생성되는 총알에 전달된다.
- [ ] 방향키를 누르고 있는 동안 설정된 간격으로 반복 발사된다.
- [ ] 방향키를 모두 놓으면 총알이 생성되지 않는다.
- [ ] 적과 충돌하면 HP가 정확히 1 감소한다.
- [ ] HP가 0이면 이동과 발사가 중지된다.

### 3.3 플레이어 총알

#### 역할

- 생성 시 전달받은 방향으로 직선 이동한다.
- 적과 충돌하면 적과 총알을 제거한다.

#### 기본 설정

| 항목 | 프로토타입 기본값 |
| --- | --- |
| 이동 속도 | 1,800 uu/s |
| 이동 방향 | 생성 시 누른 방향키의 YZ 방향 |
| 발사 입력 | 방향키 |
| 피해 | 적 즉시 처치 |

#### 이동

1. 생성 시 플레이어에게서 발사 방향을 전달받아 저장한다.
2. 저장된 방향의 X 성분을 제거하고 정규화한다.
3. 이동 속도와 `DeltaTime`을 적용해 YZ 평면에서 직선 이동한다.
4. 생성 이후에는 플레이어의 방향 입력이 바뀌어도 이동 방향을 변경하지 않는다.
5. 카메라 가시 영역을 완전히 벗어나면 총알을 제거한다.

#### 방향 입력 대응

| 발사 방향키 입력 | 월드 이동 방향 |
| --- | --- |
| 오른쪽 방향키 | +Y |
| 왼쪽 방향키 | -Y |
| 위쪽 방향키 | +Z |
| 아래쪽 방향키 | -Z |
| 오른쪽 + 위쪽 방향키 | +Y, +Z 정규화 방향 |
| 왼쪽 + 위쪽 방향키 | -Y, +Z 정규화 방향 |
| 오른쪽 + 아래쪽 방향키 | +Y, -Z 정규화 방향 |
| 왼쪽 + 아래쪽 방향키 | -Y, -Z 정규화 방향 |
| 서로 반대인 방향키만 입력 | 발사하지 않음 |
| 방향키 입력 없음 | 발사하지 않음 |

#### 충돌

1. 적과 Overlap되면 적에게 사망 처리를 요청한다.
2. 충돌 직후 총알을 제거한다.
3. 첫 충돌 이후 추가 Overlap은 처리하지 않는다.

#### 구현 체크리스트

- [ ] 네 개의 단일 방향 입력과 네 개의 대각선 입력이 올바른 YZ 방향으로 변환된다.
- [ ] 발사 후 방향키를 바꿔도 이미 생성된 총알의 방향은 유지된다.
- [ ] WASD 이동과 방향키 발사를 동시에 사용할 수 있다.
- [ ] 총알 이동 중 X 좌표가 변하지 않는다.
- [ ] 적과 충돌한 총알이 즉시 제거된다.
- [ ] 화면 밖으로 나간 총알이 제거된다.

### 3.4 적(AI)

#### 역할

- 화면 상단에 생성되어 플레이어를 추적한다.
- 플레이어와 충돌해 피해를 주고 자신은 사망한다.
- 플레이어나 플레이어 총알과 충돌하면 즉시 사망한다.

#### 기본 설정

| 항목 | 프로토타입 기본값 |
| --- | --- |
| HP | 1 |
| 이동 속도 | 300 uu/s |
| 이동 방식 | 플레이어 YZ 위치 추적 |
| 접촉 피해 | 플레이어 HP 1 감소 |

#### 이동

1. 플레이어의 현재 위치에서 X 성분을 제외한 YZ 위치를 구한다.
2. 플레이어를 향하는 방향 벡터를 정규화한다.
3. 이동 속도와 `DeltaTime`을 적용해 플레이어 방향으로 이동한다.
4. 이동 후 X 좌표를 생성 시점의 X 좌표로 고정한다.
5. 플레이어가 사망하면 이동을 중지한다.

#### 공격

1. 별도의 적 총알은 사용하지 않는다.
2. 플레이어와 Overlap되면 플레이어 HP를 1 감소시킨다.
3. 피해 적용 직후 적을 사망 처리해 중복 피해를 방지한다.

#### 피격 및 사망

1. 플레이어나 플레이어 총알과 Overlap되면 즉시 사망한다.
2. 사망 시 충돌과 이동을 비활성화한다.
3. 사망 처리를 한 번만 실행한 뒤 액터를 제거한다.

#### 구현 체크리스트

- [ ] 적이 플레이어의 YZ 위치를 향해 이동한다.
- [ ] 적 이동 중 월드 X 좌표가 변하지 않는다.
- [ ] 적과 플레이어의 충돌 시 플레이어 HP가 1 감소한다.
- [ ] 플레이어와 충돌한 적이 즉시 제거된다.
- [ ] 플레이어 총알과 충돌한 적이 즉시 제거된다.
- [ ] 한 적의 사망 처리가 중복 실행되지 않는다.

### 3.5 월드 카메라

#### 역할

- 월드의 YZ 플레이 영역에 있는 모든 액터를 월드 `+X` 방향으로 촬영한다.
- 1024×2048 기준의 세로형 Orthographic 화면을 제공한다.

#### 액터 및 컴포넌트 설정

| 항목 | 설정값 |
| --- | --- |
| 액터 타입 | CameraActor |
| 월드 위치 | (-1500, 0, 0) |
| 월드 회전 | (Pitch 0°, Yaw 0°, Roll 0°) |
| `ProjectionMode` | Orthographic |
| `AspectRatio` | 0.5 |
| `bConstrainAspectRatio` | true |
| 기준 픽셀당 월드 단위 | 2 uu |
| `OrthoWidth` | 2,048 uu |
| 세로 가시 범위 | 4,096 uu |

#### 계산 규칙

- `WorldUnitsPerReferencePixel = 2.0`을 이름 있는 설정값으로 관리한다.
- 가로 가시 범위: `1024 × 2 = 2048 uu`
- 세로 가시 범위: `2048 × 2 = 4096 uu`
- 카메라 전방은 월드 `+X`, 화면 오른쪽은 `+Y`, 화면 위쪽은 `+Z`로 설정한다.

#### 구현 체크리스트

- [ ] CameraActor 위치가 (-1500, 0, 0)이다.
- [ ] 카메라가 월드 +X 방향을 바라본다.
- [ ] Projection Mode가 Orthographic이다.
- [ ] Aspect Ratio가 0.5로 고정된다.
- [ ] Ortho Width가 2,048 uu이다.
- [ ] 세로 가시 범위가 4,096 uu이다.
- [ ] 화면 좌우가 월드 Y, 화면 상하가 월드 Z와 일치한다.
- [ ] 1024×2048 PIE 또는 Standalone에서 플레이 영역이 잘리지 않는다.

### 4.3 클래스 구성 및 책임

#### 클래스 구성 원칙

- C++ 클래스는 `Source/AIShooting/Public`과 `Source/AIShooting/Private`에 같은 폴더 구조로 배치한다.
- 핵심 규칙과 런타임 상태는 C++에 구현한다.
- Blueprint 자식 클래스는 메시, 머티리얼, 이펙트 연결과 기본값 튜닝에만 사용한다.
- YZ 이동은 직접 계산하며, XY 평면을 전제로 하는 NavMesh 이동은 사용하지 않는다.
- 입력은 Legacy Input만 사용하고 Enhanced Input 클래스에 의존하지 않는다.
- 새 인터페이스, 서브시스템, 범용 컴포넌트 계층은 프로토타입에 반드시 필요할 때만 추가한다.

#### 4.3.1 플레이어 Pawn

- 클래스명: `AAIShootingPlayerPawn`
- 부모 클래스: `APawn`
- 헤더 위치: `Source/AIShooting/Public/Player/AIShootingPlayerPawn.h`
- 구현 위치: `Source/AIShooting/Private/Player/AIShootingPlayerPawn.cpp`
- 역할:
  - PlayerController가 전달한 YZ 이동 입력을 처리한다.
  - 생성 시 X 좌표를 저장하고 이동 후 같은 값으로 고정한다.
  - 방향키 발사 벡터를 받아 플레이어 총알을 생성한다.
  - HP 감소, 사망 상태 전환, 입력 차단을 처리한다.

### 4.14 구현 검증 원칙 및 체크리스트

#### 검증 원칙

- 변경 전 관련 C++, Blueprint, Config의 기존 상태를 확인하고 사용자 변경을 보존한다.
- C++ 변경 후 `AIShootingEditor`, Win64, Development 타깃을 빌드한다.
- 빌드 성공만으로 플레이 검증을 대신하지 않는다.
- 입력, 카메라, 이동, 충돌, 게임 흐름은 1024×2048 PIE 또는 Standalone에서 직접 검증한다.
- 한 기능을 검증할 때 정상 경로, 경계값, 중복 이벤트 경로를 함께 확인한다.
- 자동화 테스트가 있는 영역은 관련 테스트를 실행한다.
- 실행하지 못한 검증은 성공으로 표시하지 않고 사유와 남은 절차를 기록한다.
- 요청과 무관한 경고나 기존 오류는 새 변경으로 인한 문제와 구분한다.

#### 정적 검증 체크리스트

- [ ] `AIShooting.Build.cs`에 필요한 모듈만 포함되어 있다.
- [ ] `EnhancedInput` 모듈과 관련 클래스 의존성이 없다.
- [ ] `DefaultInput.ini`의 기본 클래스가 Legacy `PlayerInput`과 `InputComponent`이다.
- [ ] WASD 이동 축과 네 방향 발사 액션 및 재시작 액션이 정의되어 있다.
- [ ] 모든 UObject 컴포넌트 포인터가 필요한 경우 `UPROPERTY()`로 추적된다.
- [ ] 사용하지 않는 Tick이 비활성화되어 있다.
- [ ] 에디터 노출 설정값에 Category와 적절한 `UPROPERTY` 지정자가 있다.
- [ ] `.generated.h`가 각 헤더의 마지막 include이다.

#### 빌드 검증 체크리스트

- [ ] `AIShootingEditor Win64 Development` 빌드가 성공한다.
- [ ] 새 컴파일 오류와 링크 오류가 없다.
- [ ] 프로젝트 전용 로그 카테고리를 사용한다.
- [ ] 정상 플레이 중 매 프레임 로그가 출력되지 않는다.

#### PIE 기능 검증 체크리스트

- [ ] A와 D가 월드 Y 이동만 변경한다.
- [ ] W와 S가 월드 Z 이동만 변경한다.
- [ ] 플레이어와 적의 월드 X 좌표가 이동 중 유지된다.
- [ ] WASD 이동과 방향키 발사를 동시에 사용할 수 있다.
- [ ] 방향키 단일 입력 4종과 대각선 입력 4종이 올바른 방향으로 발사된다.
- [ ] 상반된 방향키 입력이나 무입력 상태에서는 발사되지 않는다.
- [ ] 발사 후 입력 방향이 바뀌어도 기존 총알의 진행 방향은 유지된다.
- [ ] 플레이어 총알이 적과 충돌하면 둘의 충돌 처리가 한 번만 실행된다.
- [ ] 적과 플레이어가 충돌하면 플레이어 HP가 1 감소하고 적이 제거된다.
- [ ] 플레이어 HP가 0이면 이동, 발사, 적 추적, 적 생성이 중지된다.
- [ ] 재시작 입력으로 현재 레벨과 런타임 상태가 초기화된다.

#### 카메라 검증 체크리스트

- [ ] 카메라가 `(-1500, 0, 0)`에서 월드 +X 방향을 바라본다.
- [ ] Projection Mode가 Orthographic이다.
- [ ] 1024×2048 뷰포트에서 종횡비 0.5와 목표 프레이밍이 유지된다.
- [ ] 화면 좌우가 월드 Y, 화면 상하가 월드 Z와 일치한다.
- [ ] 플레이어 이동 경계와 총알 제거 경계가 실제 가시 영역과 일치한다.

### 4.15 작업 응답 원칙

- 응답 첫 부분에 요청 결과와 완료 여부를 명확하게 작성한다.
- 변경한 파일과 생성한 클래스를 나열한다.
- 중요한 설계 결정은 YZ 좌표계, 입력 방식, 카메라 기준처럼 구현에 영향을 주는 내용만 설명한다.
- 빌드, 자동화 테스트, PIE 검증 결과를 서로 구분해 작성한다.
- 각 검증은 실행 명령 또는 환경, 성공 여부, 확인한 범위를 함께 기록한다.
- 검증하지 못한 항목은 `미검증`으로 표시하고 이유와 사용자가 확인할 절차를 안내한다.
- 기존 오류나 경고를 발견하면 이번 변경으로 발생한 것인지 구분해 알린다.
- 실패가 있으면 오류 핵심 내용, 원인, 현재 상태, 다음 조치를 작성한다.
- 요청 범위를 벗어난 기능이나 리팩터링은 완료 내역에 포함하지 않는다.
- 에디터에서 추가로 연결해야 하는 Blueprint, 메시, 맵 설정은 정확한 에셋명과 속성명을 제시한다.
